# KemoMichi（獣道）設計計画（第1版）

Timelapse2 互換・クロスプラットフォーム対応のカメラトラップ画像解析アプリ。

Status: 計画のみ。コードはまだ書いていない。
Date: 2026-10-18
参照した Timelapse のバージョン: 2.5.2.0（`saulgreenberg/Timelapse` の公開ソース、README 上は 2.4.0.1 以降を公開）

この文書は実装計画の土台です。依頼内容の解釈、「互換」の定義、アーキテクチャ、
UI 改善の方針、サーバ動作、段階的なマイルストーン、リスク、未決事項をまとめています。
画面の細部やフィールド単位のスキーマ仕様は、P0（仕様化フェーズ）の成果物として別途作ります。

---

## 1. 依頼と解釈

> timelapse2 互換の完全に新しい解析アプリを作りたいです。クロスプラットフォーム対応でお願いします。
> 目的はクロスプラットフォーム対応と使いにくいUIの修正です。サーバでの動作にも対応したいです。

解釈:

- **Timelapse2** = Saul Greenberg / University of Calgary 製のカメラトラップ画像タグ付けソフト
  （WPF / .NET、Windows x64 専用）。
- **互換** = Timelapse2 の **プロジェクトファイル（`.tdb` テンプレート / `.ddb` データ）をそのまま
  開いて編集・保存でき、保存後も Timelapse2 で開ける**こと。利用者が両アプリを行き来しても
  データが壊れない・失われないことを最重要の要件とする。
- **完全に新しい** = Timelapse のコードは流用しない（後述のライセンス上の理由もある）。
  UI はゼロから設計する。
- **サーバでの動作** = 画像とデータを置いたサーバ上でアプリを動かし、ブラウザから利用できる。
  複数人での同時作業も視野に入れる。

## 2. ゴールと非ゴール

ゴール:

1. Windows / macOS / Linux のデスクトップで動く。
2. 同じソフトがサーバ（Linux、Docker）でも動き、ブラウザから使える。
3. Timelapse2 の `.tdb` / `.ddb` を**損失なく往復**できる（開く → 編集 → 保存 → Timelapse2 で開く）。
4. Timelapse2 の主要ワークフロー（画像閲覧・タグ入力・検索・一括入力・エピソード・認識結果の
   取り込み・CSV 出力）をすべてカバーする。
5. Timelapse2 の使いにくさを解消した UI（§6）。
6. 100 万枚規模でも固まらない（Timelapse 自身が「全件を一度にメモリに読む」ことを最大の
   待ち時間の原因として挙げている。`PotentialImprovements.md` L-1）。

非ゴール（第1版では扱わない）:

- AI 推論そのもの（AddaxAI / MegaDetector の役割。結果ファイルを取り込む側に徹する）。
- Timelapse2 の全メニュー項目の 1:1 再現。使われていない機能は利用者ヒアリング後に判断。
- クラウド SaaS としての多テナント運用。
- モバイル端末向けの最適化（タブレットでの閲覧は可能な程度に留める）。

## 3. 「互換」の定義

互換性を段階で定義し、どこまで保証するかを明確にする。

| レベル | 内容 | 第1版 |
|---|---|---|
| C1 読み込み | `.tdb` / `.ddb` を開き、全データを正しく表示 | 必須 |
| C2 往復保存 | 編集して保存した `.ddb` を Timelapse2 が警告なく開け、未編集データはビット単位で不変 | 必須 |
| C3 新規作成 | 本アプリで作った `.tdb` / `.ddb` を Timelapse2 が開ける | 必須 |
| C4 認識結果 | MegaDetector 形式 / AddaxAI の `addaxai-recognitions.json` を取り込み、Timelapse と同じテーブル（`Info`, `DetectionCategories`, `ClassificationCategories`, `Detections`, `DetectionsVideo`）に格納 | 必須 |
| C5 CSV | Timelapse2 と同じ列構成・書式の CSV 出力と取り込み | 必須 |
| C6 その他出力 | CamtrapDP 出力、バックアップ（`Backups/`）、削除ファイル退避（`DeletedFiles/`）の同じ流儀 | P4 |
| C7 設定の保持 | `ImageSetTable` の `SortTerms` / `SearchTerms` / `QuickPasteTerms`（JSON）を読み書き | P4 |

ソースで確認したファイル構造（P0 で詳細仕様化する）:

- `.tdb`（テンプレート）: `TemplateTable`, `TemplateInfo`, フォルダ階層データ用の
  `FolderDataTemplateTable`, `FolderDataInfo`。
- `.ddb`（データ）: 上記テンプレート表のコピーに加え、`DataTable`（1 行 = 1 ファイル。
  標準列 `File`, `RelativePath`, `DateTime`, `DeleteFlag` + 利用者定義列）, `ImageSetTable`,
  `MarkersTable`, フォルダ階層ごとのデータ表、認識結果の各表。
- テンプレートのコントロール属性: `Type`, `DefaultValue`, `Label`, `DataLabel`, `Tooltip`,
  `TXTBOXWIDTH`, `Copyable`, `Visible`, `List`, `ControlOrder`, `SpreadsheetOrder`,
  `ExportToCSV`, `Level` など。
- コントロール型: `Counter`, `FixedChoice`, `MultiChoice`, `Flag`, `Note`, `MultiLine`,
  `AlphaNumeric`, `IntegerAny`, `IntegerPositive`, `DecimalAny`, `DecimalPositive`,
  `DateTime_`, `Date_`, `Time_`。
- 互換バージョン管理: `ImageSetTable` の `VersionCompatabily`（原文の綴りのまま）と
  `BackwardsCompatibility`。Timelapse は `2.3.0.0` 未満を非対応としている。

互換のための設計ルール:

1. **`.ddb` が唯一の正（source of truth）**。自前 DB に取り込んで書き戻す方式は取らない。
   取り込み・書き戻しのどこかで情報が落ちる経路を作らないため。
2. **知らないテーブル・列・値は触らない**。将来の Timelapse が追加したものも温存する。
3. **`.ddb` に独自テーブルを足さない**。本アプリ固有の情報（編集者、編集ロック、監査ログ、
   UI 状態）は別ファイル（サイドカー SQLite、例 `<name>.ddb.review`、または
   アプリデータ領域）に置く。
4. **`journal_mode` を WAL のまま残さない**。WAL はファイルに永続化され、Timelapse 側は
   それを戻す処理まで入れている（`FileDatabase.cs` の `RevertJournalModeFromWalIfNeeded`）。
   デスクトップ版は既定のロールバックジャーナルで書く。
5. **`BackwardsCompatibility` を勝手に上げない**。上げると Timelapse2 の旧版が開けなくなる。
   対応外の新しいバージョンの `.ddb` は読み取り専用で開き、その旨を表示する。
6. **書き込み前に自動バックアップ**（Timelapse と同じ `Backups/` 流儀）。

ライセンス上の注意:

- Timelapse は **CC BY-NC-SA 4.0**。本アプリは商用利用を可能にするため **MIT** とする。
  Timelapse のコードを写すと NC（非営利）と SA（継承）が本アプリに及ぶ。
  **コードは一切流用せず、ファイル形式は実ファイルの観察と公開ドキュメントから独自に仕様化する**
  （クリーンルーム方式）。ソースを読む担当と実装する担当を分けるのが望ましい。
- 名称に「Timelapse」を使わない（混同防止）。アプリ名は **KemoMichi** とする。

## 4. アーキテクチャ

AddaxAI と同じ「ローカル Web サーバ + Web UI」構成を採る。AddaxAI は既にこの構成で
Electron の中身はブラウザであり、サーバ化の調査（AddaxAI リポジトリの `future-plans/multi-user-verification.md`）で
「ほぼそのまま Web アプリとして動く」ことが確認されている。これを最初から意図して設計する。

```
            ┌────────────────── 同一の Web UI（React SPA）──────────────────┐
            │                                                              │
   デスクトップ版                     サーバ版                         CLI
  ┌───────────────┐          ┌───────────────────────┐        ┌──────────────┐
  │ Electron 殻    │          │ ブラウザ（各利用者）     │        │ kemo CLI     │
  │  └ SPA 表示    │          └──────────┬────────────┘        │ 検証/CSV出力/ │
  │  └ ネイティブ   │                     │ HTTPS               │ 認識取込     │
  │    フォルダ選択 │          ┌──────────┴────────────┐        └──────┬───────┘
  └──────┬────────┘          │ リバースプロキシ(TLS)    │               │
         │ http://127.0.0.1  └──────────┬────────────┘               │
  ┌──────┴──────────────────────────────┴────────────┐               │
  │ API サーバ（FastAPI）  認証 / WebSocket / 画像配信  │               │
  └──────────────────────┬───────────────────────────┘               │
  ┌──────────────────────┴───────────────────────────────────────────┴──┐
  │ コアライブラリ kemocore（純 Python、UI・HTTP 非依存）                      │
  │  .tdb/.ddb 読み書き・テンプレート・検索→SQL・エピソード・日時補正・        │
  │  認識結果取込・CSV/CamtrapDP 出力・バックアップ                          │
  └──────────────────────┬──────────────────────────────────────────────┘
          .tdb / .ddb（SQLite）  画像・動画  サイドカー  サムネイルキャッシュ
```

要点:

- **コア（kemocore）を UI からも HTTP からも切り離す**。互換性の要はここに集中させ、
  単体テストで徹底的に固める。CLI もこれを直接使う。
- **デスクトップ版とサーバ版は同じバイナリ・同じ UI**。違いは設定（待受アドレス、認証、
  閲覧可能なルートフォルダ）だけ。
- Electron 殻は薄く保つ（フォルダ選択、ファイルを OS で開く、メニュー程度）。
  将来 Tauri に替えられる程度の依存に留める。

技術選定と理由:

| 層 | 採用 | 理由 / 比較した代替 |
|---|---|---|
| コア・API | Python 3.13, FastAPI, SQLite（標準 `sqlite3`。`.ddb` の列は動的なので ORM は使わない） | AddaxAI と同じで知見・パッケージング手順（PyInstaller）を流用できる。EXIF（ExifTool）、画像（Pillow）、動画（ffmpeg）も揃う。代替の Rust + Tauri は軽量だが全て作り直しになり、.NET + Avalonia はブラウザ／サーバ動作に向かない。 |
| UI | React + TypeScript + Vite, TanStack Query / Router / Virtual, Radix UI | AddaxAI と同じ。仮想スクロールで大量データに対応。 |
| 画像表示 | Canvas（Konva）| 拡大鏡・ズーム・BBox・マーカー・差分表示。AddaxAI で実績あり。 |
| デスクトップ殻 | Electron（バックエンドをサイドカー起動） | AddaxAI の起動・更新・署名の仕組みを流用。 |
| サーバ配布 | Docker イメージ + docker compose 例 | 1 コマンドで起動できる形に。 |
| 動画 | ブラウザ再生可能な形式はそのまま、AVI / ASF などはサーバ側 ffmpeg でオンデマンド変換 | ブラウザは AVI を再生できないため。 |

## 6. UI 設計方針（使いにくさの解消）

利用者から挙がった不満（確定）:

- **タブ移動で獣種を選ぶのがやりにくい**（§6.1）。
- **REST 法の計測で必要な三角形の補助線を引けない**ため、別アプリを画面に重ねている（§6.2）。

一般に挙がる不満（利用者も問題と認識）:

- メニューが深く、機能が見つからない。ショートカットも覚えにくい。
- 検索（カスタム選択）がモーダルダイアログで、条件を変えるたびに開き直す。
- データ入力パネルが窮屈で、レイアウトの自由度が低い。
- テンプレート編集が別アプリで、変更の結果がすぐ見えない。
- 大規模データで全件選択すると固まる。
- 高 DPI・ダークモード・多言語に弱い。Windows 以外で動かない。

方針:

1. **1 画面 3 ペイン**: 左 = フォルダツリーとフィルタ、中央 = ビューア／グリッド切替、
   右 = データ入力。ペインは幅変更・折りたたみ可能、レイアウトは保存。
2. **コマンドパレット（Ctrl/⌘+K）** から全機能に到達。`?` でショートカット一覧、
   ショートカットは変更可能。
3. **フィルタはチップ形式で常時表示**。条件変更が即座に結果へ反映され、件数も常に見える。
   よく使う条件は名前を付けて保存（Timelapse の `SearchTerms` と相互変換）。
4. **一括入力はグリッドで選択 → 右パネルが「N 件に適用」モードに切り替わる**。
   適用前に差分プレビュー。
5. **全編集を Undo / Redo 可能**。自動保存の状態を常に表示。破壊的操作だけ確認ダイアログ。
6. **キーボードだけで流れ作業が完結**（次へ、値入力、次へ…）。タグ付けの手数を計測して改善する。
7. **大規模データ前提**: 仮想スクロール、ページング取得、サムネイルは事前生成キャッシュ。
8. **テンプレートエディタ内蔵**: 右パネルの見た目をその場でプレビューしながら編集。
9. **新規作成はウィザード**: フォルダ選択 → テンプレート選択／作成 → 走査 → 日時確認。
10. ダークモード、高 DPI、日本語・英語。

P2 の早い段階で動くプロトタイプを利用者に触ってもらい、方針を検証する。

### 6.1 獣種選択の改善

実際のテンプレートを調べると、獣種は **1 種ごとに独立した Flag（true/false）コントロール**として
定義されている。Timelapse2 ではこれを Tab で 1 つずつ移動してチェックするため手数が多い。

- **データ形式は変えない**（Timelapse2 と往復するため、Flag 列のまま読み書きする）。
- UI 上で複数の Flag を **「種選択パレット」としてまとめて表示**する。
  - 各種に数字キー／英字キーを割り当て、1 キーで ON/OFF。
  - 種名の頭文字を打つと絞り込み（インクリメンタル検索）。
  - 大きめのボタンをクリック・タップでも選べる。よく使う種を上に並べる。
  - 「1 枚に 1 種のみ」モード（選ぶと他を OFF）と「複数選択可」モードを切替。
- どの Flag をパレットにまとめるか、キー割り当て、並び順は**サイドカーに保存**し、`.ddb`／`.tdb` は変更しない。
  初回は Flag 型を自動検出して候補を提示する。
- 個数（Counter）の入力は、種を選んだ直後にフォーカスが移るようにして、「種 → 個数 → 次の画像」を
  キーボードだけで完結させる。

### 6.2 REST 法のためのガイド線（補助線）

REST（Random Encounter and Staying Time）法では、画面内に定めた領域（多くは三角形）への
侵入・退出を判定するため、補助線が必要。Timelapse2 にはこの機能がない。

- **ガイドを画像に重ねて表示**: 多角形（三角形など）・線分・点を描ける。色・太さ・不透明度を設定、
  1 キーで表示／非表示を切替。
- **カメラ（フォルダ = `RelativePath`）ごとに定義**し、同じカメラの全画像・全動画に自動で適用。
  別カメラからのコピー、期間ごとの切替（カメラの向きが変わった場合）に対応。
- 座標は**画像サイズに対する相対座標**で保存し、解像度の違う画像や動画でもずれない。
- ガイド定義はサイドカーに保存し、JSON で書き出し・読み込みできる（Timelapse2 側には影響しない）。
- 拡大・パンしてもガイドが画像に追従する。動画再生中も表示する。
- 将来（P4 以降の検討事項）: 個体の位置をマーカーで打ったときに領域内外を自動判定、
  侵入・退出フレームの時刻から滞在時間を自動計算してデータ列に入力。

### 6.3 テンプレート調査から得た設計上の注意

- 非表示（`Visible=false`）のコントロールが残っていることがある。表示はしないが**必ず温存**する。
- 数値を入れる用途に Note（文字列）型が使われていることがある。型は変えず、UI 側で
  「数値入力」「時刻入力」などの入力補助をサイドカー設定で付けられるようにする。
- 真偽値は文字列 `true` / `false` として格納されている。
- 調査したテンプレートは 2.5.1 系で保存され、`BackwardsCompatibility` は 2.3.0.0、`journal_mode` は `delete`。

## 7. サーバ動作

### 7.1 動作モード

| モード | 待受 | 認証 | フォルダ選択 | 想定 |
|---|---|---|---|---|
| デスクトップ | 127.0.0.1 | なし | OS のダイアログ | 個人 PC |
| LAN サーバ | LAN | 必須 | 許可したルート配下をブラウザ内で閲覧 | 研究室の共有 PC / NAS 横のサーバ |
| リモートサーバ | リバースプロキシ経由（HTTPS） | 必須 | 同上 | クラウド VM・学内サーバ |
| CLI | なし | なし | 引数 | バッチ処理、CI |

### 7.2 安全側の既定値

- 非ループバックで待ち受けるのに認証が無効なら**起動を拒否**する
  （AddaxAI 計画の R3 と同じ考え方）。
- ブラウザから見えるのは設定で許可したルートフォルダ配下だけ。パス・トラバーサルを
  サーバ側で検証。
- TLS はリバースプロキシ（Caddy / nginx）に任せ、compose の例を同梱。
- WebSocket も HTTP と同じ認証ミドルウェアを通す。

### 7.3 認証と編集者の記録

- 第1段階: 共有パスワード + 利用者名の自己申告（編集者記録用）。最小構成で運用開始できる。
- 第2段階（必要なら）: 利用者アカウントと OIDC（学内 SSO 等）。
- 編集者・時刻はサイドカーの監査ログに記録（`.ddb` には書かない、§3 ルール 3）。

### 7.4 複数人同時編集

- `.ddb` への書き込みは**サーバ内の単一ライターキュー**で直列化する（SQLite の性質に合わせる）。
- 行単位の楽観ロック: 各利用者は読み込み時の版を持ち、競合したら差分を見せて選ばせる。
- 他の人の編集は WebSocket で即時反映。誰がどのフォルダを作業中かを表示。
- 作業分担はフォルダ（`RelativePath`）単位の割り当てを基本にする。

### 7.5 帯域と性能

- 画像は原寸ではなく表示サイズのプレビュー（WebP/JPEG）を配信し、拡大時だけ原寸を取得。
- サムネイル・プレビューはサーバ側でバックグラウンド生成しキャッシュ。
- 長時間処理（走査、EXIF 読取、認識結果取込、出力）はジョブ化して進捗を WebSocket で配信。

### 7.6 注意: ネットワーク共有上の SQLite

`.ddb` を SMB/NFS 共有に置いて**複数の PC から直接**開くと、SQLite のロックが信頼できず
壊れる恐れがある（Timelapse2 でも同じ）。複数人で使うなら「サーバ版 1 台が `.ddb` を持ち、
他はブラウザ」を推奨構成とし、共有ドライブ上の `.ddb` を開いたときは警告を出す。
また、Timelapse2 と本アプリで同じ `.ddb` を同時に開いた場合の検出と読み取り専用化を実装する。

## 8. リポジトリ構成（案）

独立したリポジトリ `HKimura787/KemoMichi` とする（AddaxAI とはコードを共有しない。
連携は認識結果ファイルと将来の API で行う）。

  server/                   # FastAPI アプリ、認証、ジョブ、画像配信

  docs/                     # 設計計画（本書）、P0 で作るファイル形式仕様書

## 10. テスト戦略

- **往復テスト（最重要）**: フィクスチャを開く → 編集なしで保存 → 元ファイルと
  スキーマ・全行を比較して差分ゼロ。編集ありの場合は編集箇所以外が不変であること。
- **Timelapse2 での実機確認**: リリースごとに、本アプリで編集・作成したファイルを
  Windows 上の Timelapse2 で開く手順を自動化（Windows ランナー上で起動確認できる範囲）と
  手動チェックリストで確認。
- **プロパティテスト**: ランダムなテンプレートとデータで書いて読んで一致すること。
- **E2E**: Playwright で Web UI（デスクトップ版もブラウザ経由で同じテストを流す）。
- **CI マトリクス**: Windows / macOS / Linux。
- **性能**: 100 万行の合成 `.ddb` で、開く・フィルタ・スクロール・一括入力の所要時間を計測し、
  劣化を CI で検出。
- **同時実行**: サーバ版で複数クライアントから同時書き込みし、`PRAGMA integrity_check` と
  期待値を比較。

## 11. リスク

| リスク | 影響 | 対策 |
|---|---|---|
| ファイル形式が非公開仕様で、Timelapse の更新で変わる | 互換が壊れる | 未知の要素は温存、バージョン判定で新しすぎる DB は読み取り専用、Timelapse の新版ごとにフィクスチャ追加 |
| ライセンス（CC BY-NC-SA） | 本アプリの MIT が成り立たなくなる | クリーンルーム、コード流用禁止を規約化 |
| 共有ドライブ上の SQLite | データ破損 | 推奨構成の明示、検出して警告、自動バックアップ |
| Timelapse2 と同時オープン | 書き込み競合 | ロック検出で読み取り専用化 |
| ブラウザで再生できない動画形式 | 動画が見られない | サーバ側 ffmpeg 変換、デスクトップ版も同じ経路 |
| EXIF 日時の解釈差 | 日時が Timelapse と食い違う | フィクスチャで Timelapse の取り込み結果と比較 |
| 範囲の肥大化 | 完成しない | P2 で MVP を利用者に当て、P4 の優先度を再判定 |

## 12. AddaxAI との関係

- 当面は既存の流れを維持: AddaxAI が `addaxai-recognitions.json` を画像フォルダに書き、
  本アプリが取り込む（Timelapse2 と同じ）。
- P6 で、本アプリから AddaxAI の解析を起動し、完了時に自動で取り込む連携を追加
  （AddaxAI 側の `--timelapse <folder>` 起動引数と同等の入口を用意）。
- 両者を同じサーバに同居させる構成も可能にする（ポートとルートフォルダを分ける）。
