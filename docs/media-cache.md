# メディアキャッシュ

サムネイル、プレビュー、動画フレーム情報、ブラウザ再生用の変換動画を保存します。
元の画像・動画、ddb、補助ファイル、`Backups/` は削除しません。

## 保存先

- macOS / Linux：`~/.cache/kemomichi`。`XDG_CACHE_HOME` がある場合はその下の `kemomichi/`。
- Windows：`%LOCALAPPDATA%\KemoMichi\cache`。
- `KEMOMICHI_CACHE` を設定すると、保存先を変更できます。

## 容量上限

既定は **2 GiB（2,147,483,648バイト）** です。
`KEMOMICHI_CACHE_MAX_BYTES` に0以上の整数を設定すると、バイト単位で変更できます。
不正な値や負数の場合は警告をログに記録し、既定値を使います。
保存先を指定する `KEMOMICHI_CACHE` とは別の設定です。

例：上限を5 GiBにしてCLI版を起動する場合。

macOS / Linux：

```sh
KEMOMICHI_CACHE_MAX_BYTES=5368709120 uv run kemo serve
```

Windows（PowerShell）：

```powershell
$env:KEMOMICHI_CACHE_MAX_BYTES = "5368709120"
uv run kemo serve
```

補助アプリ版でも同じ変数を参照します。補助アプリを起動するプロセスに環境変数を設定してください。

## 整理のタイミングと保護するファイル

- キャッシュの生成に成功するたびに、完成済みキャッシュの合計容量を調べます。
- 上限を超えた場合、最終利用が古いファイルから、上限以下になるまで削除します。
  再利用時はキャッシュファイルの更新日時を更新し、これを最終利用日時として使います。
  OSのアクセス日時の自動更新に依存せず、元ファイルの日時は変更しません。
- 上限内の場合は、既存キャッシュを削除しません。
- 生成途中は一時ファイルへ書き、成功後に完成ファイルへ置き換えます。
  一時ファイルは削除対象・完成済みキャッシュの容量集計から除外します。
  失敗・中断時は、その処理が作った一時ファイルを削除します。
- 今回要求されたキャッシュと、同じプロセスで生成・読み込み・HTTP配信中のキャッシュは保護します。
  今回の1ファイルだけで上限を超える場合も生成を続け、そのファイルを保持します。
  この場合や保護中・削除不能なファイルがある場合は、一時的に上限を超えることがあります。
- `0` の場合も生成は続けます。書き込み時に保護対象以外の既存キャッシュを削除します。
- 整理対象は、従来のものを含むKemoMichi形式の完成ファイル（SHA-1名の `.jpg`・`.json`・`.mp4`・`.webm`）です。
  シンボリックリンク、サブフォルダ、その他のファイルは削除しません。

キャッシュを空にしても、次に対象を表示した際に作り直します。
ブラウザの `Cache-Control` と、このディスク上の容量上限は別です。
