# KemoMichi デザインシステム（第2版）

- 作成日: 2026-10-18（第2版: 明るめの青に変更、ライトテーマのみに整理、デジタル庁デザインシステムに準拠）
- 対象: KemoMichi のアプリ画面（デスクトップ版・サーバ版の Web UI 共通）
- 状態: 提案段階。P2a の実装開始前に確定する（§11 確認事項）
- 準拠: [デジタル庁デザインシステム](https://design.digital.go.jp/)。色・書体・角の丸み・影は、デジタル庁が MIT ライセンスで公開している
  デザイントークン `@digital-go-jp/design-tokens` 2.0.1 の値をそのまま使う（トークン名を併記）。
  アクセシビリティの基準（コントラスト、フォーカス表示、エラー表示）もデジタル庁の規則に合わせる。

## 1. 基本方針

- **明るめの青を基調**にし、有彩色は役割で **3 つ（主色・面・アクセント）** に絞る。
- 面積の目安は、ベース（白・灰色）70%、主色と面 25%、アクセント 5%。
  アクセントは画面の中で「いちばん大事な 1 か所」にだけ使う。
- アクセントは主色と**明るさと色相の両方で**区別する。
- **色だけで意味を伝えない**。状態や区別には必ず文字・形・アイコンを添える
  （色覚の違い、夜間の赤外線画像のようなモノクロ画面、白黒印刷でも読めるようにする）。
- 区切りは面の色の違いと余白で作る。塗りつぶした部品に見える枠線は付けない（§2.4）。
- グラデーション・立体表現は使わない。影はデジタル庁のエレベーションを、**浮かぶ層（メニュー、ダイアログ、
  コマンドパレット、通知）にだけ**使う（§2.8）。
- **写真が主役**。画像を見る領域のまわりは色を持たない暗い灰色にし、UI の青が画像の色の見え方に
  影響しないようにする（§2.6）。色味調整（計画書 §6.4）の判断を狂わせないため。
- テーマは**ライトテーマのみ**（ダークテーマは作らない）。
- 色を決める・変えるときは、`tools/color_check.py` でコントラスト比と色覚シミュレーション
  （1 型・2 型・3 型）を計算して確かめる。

## 2. 色

### 2.1 パレット

**推奨案 A: 明るい青**

| 役割 | トークン（KemoMichi） | 値 | デジタル庁トークン | 主な用途 |
|---|---|---|---|---|
| 主色 | `color.primary` | `#0066BE` | light-blue-800 | 上部バー、選択中の状態、アイコン、副ボタンの文字と線、パネル見出しの文字 |
| 主色・濃 | `color.primary-strong` | `#00428C` | light-blue-1000 | リンク、押している間、選択中にマウスを重ねたとき |
| 面 | `color.surface` | `#E8F1FE` | blue-50 | パネルの見出し行、表の見出し行、マウスを重ねたとき |
| アクセント | `color.accent` | `#F08A00` | （KemoMichi 独自） | 主ボタン（1 画面に 1 つ）、タイムラインの再生位置 |

**比較案 B: 鮮やかな青**（デジタル庁のキーカラーそのまま）

| 役割 | 値 | デジタル庁トークン |
|---|---|---|
| 主色 | `#0031D8` | blue-800（key-800） |
| 主色・濃 | `#00118F` | blue-1000（key-1000） |
| 面 | `#E8F1FE` | blue-50（key-50） |
| アクセント | `#F08A00` | （KemoMichi 独自） |

- 案 A は明るく軽い印象で、白に対して 5.76（文字の基準 4.5 を満たす）。
  ただしアクセントとの明るさの差が 2.29 と小さいため、**アクセントを主色の上に置かない**（§2.2）。
- 案 B は鮮やかで力強い印象。白に対して 8.64、アクセントとの差も 3.43 あり、配置の制約が少ない。
- 主色・濃は主色と同じ系統の濃淡で、色の数には数えない。
- アクセントの橙は、デジタル庁の警告色（orange-600 `#FB5B01`）と近いため、警告には橙を使わない（§2.5）。

**無彩色**（デジタル庁 solid-gray）

| 役割 | 値 | トークン | 用途 |
|---|---|---|---|
| 本文 | `#1A1A1A` | solid-gray-900 | 本文、主ボタンの文字 |
| 補足 | `#4D4D4D` | solid-gray-700 | 注記、ファイル名、時刻 |
| 境界（意味のある線） | `#767676` | solid-gray-536 | 入力欄の枠、区切りの中でも部品の境界を示すもの（白に 4.54） |
| 区切り | `#CCCCCC` | solid-gray-200 | 表の行の区切り、ペインの境界（飾りの線） |
| 地 | `#F2F2F2` | solid-gray-50 | ツールバーの背景など、白と区別したい地 |
| 白 | `#FFFFFF` | white | 地 |

### 2.2 アクセントの使い方

- 使う場所
  - **主ボタン**: その画面でいちばん大事な操作 1 つ（例:「読み込む」「書き出す」「計測を確定」）。
    塗りはアクセント、文字は本文の太字（6.91）。**白い文字は載せない**（2.52 で不可）。
  - **タイムラインの再生位置**（動画・連続画像の現在位置の縦線と三角）。ビューアの灰色の上なので 5.02 で見える。
- 使わない場所
  - 白・面の上の文字色、細い線（白に 2.52 で不可）
  - **主色の上**（案 A では 2.29 で区別しにくい。上部バーの「未保存」の印は白い札の中に置く）
  - フォーカス表示、リンクの下線（フォーカスの黄と取り違えないため）
  - 警告・エラーの表示とその近く
  - グラフの系列、種の色分け（§2.7 の注釈色を使う）
- 面積は全体の 5% 前後に収める。

### 2.3 コントラスト比（案 A。`tools/color_check.py` で計算）

デジタル庁の基準: 文字は 4.5:1 以上（大きな文字は 3:1 以上）、アイコン・線・部品の境界は 3:1 以上。

| 前景 | 背景 | 比 | 使い方 |
|---|---|---:|---|
| 白 | 主色 | 5.76 | 可: 上部バーの文字、選択中のチップ・行の文字 |
| 主色 | 白 | 5.76 | 可: アイコン、副ボタン、強調文字 |
| 主色 | 面 | 5.06 | 可: パネル見出しの文字・アイコン |
| 主色・濃 | 白 | 9.73 | 可: リンク |
| 白 | 主色・濃 | 9.73 | 可 |
| 本文 | 白 / 面 | 17.40 / 15.29 | 可 |
| 補足 | 白 / 面 | 8.45 / 7.42 | 可 |
| 境界 | 白 | 4.54 | 可: 入力欄の枠（3:1 以上） |
| 本文 | アクセント | 6.91 | 可: 主ボタンの文字 |
| アクセント | 主色 | 2.29 | **不可**: 主色の上にアクセントを置かない |
| アクセント | 白 | 2.52 | **不可**（文字・意味のある線）。主ボタンの塗りには使える |
| 面 | 白 | 1.14 | 面の区別だけに使い、境界の意味を持たせない |

### 2.4 枠線

- 塗りつぶした部品（ボタン、チップ、選択中の行、バー）の枠線は塗りと同じ色にする（見える枠を付けない）。
- 例外: 押せる・入力できる部品で、塗りが背景とほとんど区別できない（比 1.5 未満）ものには、
  3:1 以上の線を付ける（デジタル庁の規則）。
  - 副ボタン: 主色の 1px の線。
  - 入力欄・選択欄: 境界の灰 `#767676` の 1px。マウスを重ねたら本文色、入力中はフォーカス表示。
- 飾りの区切り（表の行、ペインの境界）は区切りの灰 `#CCCCCC` の 1px。

### 2.5 状態の色（例外色。装飾には使わない）

デジタル庁のセマンティックカラーを使う。いずれも**アイコンと文言を必ず添える**。

| 状態 | 表示 | トークン |
|---|---|---|
| フォーカス | 黄 `#FFD43D` と黒の二重線。どの部品でも同じ。デジタル庁の規則どおりで、変えない | yellow-300 |
| エラー | 文字と線は赤 `#CE0000`（白に 5.79）、アイコンは `#EC0000` も可。必ず「何が起きたか」と「どうすればよいか」を書く | error-2 / error-1 |
| 警告 | 文字とアイコンは暗い黄 `#927200`（白に 4.54）。**白地に置く**（面の上では 3.98 で文字の基準に届かない）。**橙は使わない**（アクセントと区別するため） | warning-yellow-2 |
| 成功・保存済み | 文字とアイコンは緑 `#197A4B`（白に 5.35） | success-2 |
| 選択中 | 主色の塗り＋白文字、またはサムネイルでは主色の 3px の線＋選択番号の札。フォーカス表示とは形で区別できる | — |
| マウスを重ねた | 面の色の塗り。文字の色は変えない。リンクは下線を太くする | — |
| 無効 | 補足の灰の文字＋区切りの灰の線。使えない理由をツールチップで示す | — |

### 2.6 画像ビューアの色

- 画像の周囲（ビューア・動画プレイヤー・拡大鏡・サムネイル一覧の背景）は**色を持たない暗い灰色**
  `#333333`（solid-gray-800）。UI の青が画像の色の見え方に影響しないようにする。
- ビューア上のボタン・時刻表示は白（12.63）。再生位置のアクセントは 5.02 で見える。

### 2.7 画像上の注釈色（例外色）

BBox・ポイント・キーポイント・ガイド図形は、さまざまな写真（昼の緑、夜の赤外線のモノクロ、逆光）の上に
重ねるため、UI の色とは別に**注釈専用の色**を持つ。

- 種などの区別には、色覚の違いに配慮して作られた 8 色の配色（Okabe & Ito, 2008）を使う:
  `#E69F00` 橙、`#56B4E9` 空色、`#009E73` 青緑、`#F0E442` 黄、`#0072B2` 青、`#D55E00` 朱、
  `#CC79A7` 赤紫、`#FFFFFF` 白。
- どんな写真の上でも見えるよう、線と点には**黒の縁取り（1px）**を付ける。ラベルは黒地に白文字の小さな札。
- **色だけで区別しない**: BBox・ポイントには必ず種名（または略号）と番号の札を付ける。
  キーポイントは部位ごとに形（丸・四角・三角）も変える。
- ガイド図形（REST の領域など）は既定で白の線＋黒の縁取り、塗りは半透明（不透明度 15%）。利用者が変更できる。
- AI の候補は破線、人が確定したものは実線で区別する（色は同じ）。
- 割り当ては利用者が変更でき、9 種目以降は形と札で区別する。

### 2.8 影（エレベーション）

- 画面に固定された部分（バー、ペイン、表）には影を付けない。
- 浮かぶ層にだけ、デジタル庁のエレベーションを使う:
  メニュー・ツールチップ elevation-1、通知 elevation-2、ダイアログ・コマンドパレット elevation-3。

### 2.9 グラフ

- 系列は主色の青の濃淡（light-blue の 300〜1000）を使う。2 系列までは色ではなく形で分ける
  （実線と破線、塗りと白抜き）。系列名は線の横に直接書く。
- 3 系列以上を色で分ける必要があるときは注釈色（§2.7）を使い、凡例ではなく直接ラベルを付ける。
- 値ラベルには分母を併記する（例: 12 / 340 枚）。

## 3. 書体と文字

### 3.1 書体（デジタル庁のトークン）

| 用途 | 書体 |
|---|---|
| UI 全般 | `'Noto Sans JP', -apple-system, BlinkMacSystemFont, sans-serif`（font-family-sans） |
| 時刻・タイムコード・フレーム番号 | `'Noto Sans Mono', monospace`（font-family-mono） |
| 数値の列 | UI の書体で等幅数字（`font-variant-numeric: tabular-nums`） |

- 太さは 400 と 700 の 2 段階（font-weight-400 / 700）。
- Noto Sans JP / Noto Sans Mono はアプリに同梱する（オフラインでも同じ表示にするため）。
- 日本語と英語で同じ書体・同じ文字サイズを使う。

### 3.2 文字サイズ

デジタル庁の文字サイズのトークン（14〜64px）から選ぶ。アプリは情報量が多いので、デジタル庁の「密な表示」
向けの小さめの組み合わせを基本にする。利用者は UI 全体の拡大率（90〜150%）で大きくできる。

| 要素 | サイズ / 太さ | 行間 | 字間 |
|---|---|---|---|
| ダイアログ・ウィザードの見出し | 22px / 700（font-size-22） | 1.5 | 0.02em |
| パネルの見出し | 16px / 700（font-size-16） | 1.4 | 0.02em |
| 本文・入力欄・ボタン | 16px / 400（ボタンは 700） | 1.5 | 0.02em |
| 表・一覧の行、補足、密なパネル | 14px / 400（font-size-14） | 1.4 | 0.02em |
| 画像上の札、ツールチップ | 14px / 700 | 1.3 | 0.02em |

- **14px 未満は使わない**（デジタル庁のトークンの最小値）。
- 文章（ヘルプ、説明文）は行間 1.7。

## 4. 間隔・寸法・角の丸み

- 8px 単位を基本にし、密な部分だけ 4px を使う（4 / 8 / 16 / 24 / 32 / 40）。
- ボタンの高さ（デジタル庁のボタンの大きさに合わせる）: 大 56px（ウィザードの主操作）、中 48px、小 36px（ツールバー、パネル内）。
  密な表の中の操作は 28px まで。
- 押せる部品の最小の大きさは 36px（マウス）、タッチ操作のある画面は 44px。
- 角の丸み（border-radius トークン）: ボタン・入力欄・チップ 8px、タイムラインの区間の帯・札 4px、
  ダイアログ・メニュー 12px。パネル、バー、表、画像、サムネイルは直角。
- 線の太さ: 区切り 1px、選択中 3px。

## 5. 画面の構成

- **上部バー**: 主色の塗りに白文字。プロジェクト名、接続先（「この PC」／サーバ名）、保存状態（白い札の中に表示）、
  言語切替、設定。高さ 48px。
- **3 ペイン**: 左（フォルダとフィルタ）・中央（ビューア／グリッド）・右（データ入力）。
  左右のパネルは白地、パネルの見出し行は面の色。中央はビューアの灰色（§2.6）。
- **下部**: 動画・連続画像のタイムライン（中央ペインの下）。背景はビューアの灰色、再生位置はアクセント。
- ペインの境界は区切りの灰の 1px。

## 6. 部品

- **主ボタン**: アクセントの塗り＋本文の太字。1 画面に 1 つまで。枠は付けない。
- **副ボタン**: 白地＋主色の文字＋主色の 1px の線。
- **テキストボタン**（控えめな操作）: 塗りなし、主色の文字＋下線。
- **アイコンボタン**（ツールバー）: 塗りなし、主色のアイコン。マウスを重ねると面の色。
  アイコンだけのボタンには必ずツールチップ（機能名＋ショートカット）を付ける。
- **入力欄**: 白地＋境界の灰 1px。エラー時は赤の線 2px＋下にエラー文言（アイコン付き）。
  必須項目は「必須」の文字で示す（色や記号だけにしない）。
- **チップ**（フィルタ条件、選択中の種）: 選択中は主色の塗り＋白文字、未選択は面の塗り＋主色の文字。削除ボタン（×）付き。
- **種選択パレット**: 種ごとのボタン（最小 44×44px）に、種名・割り当てキー・個数を表示。
  ON は主色の塗り＋白文字＋左上の小さな四角の印、OFF は白地＋主色の線。ON/OFF は色に加えて印の有無でも区別する。
- **表**: 見出し行は面の色、本文行は白。縦の罫線は引かず、横の区切りは区切りの灰 1px。選択中の行は主色の塗り＋白文字。
- **サムネイル**: 直角。選択中は主色の 3px の線＋左上に選択番号の札。削除フラグ付きは右上に「削除」の札（色だけで示さない）。
- **タイムライン**: 再生位置はアクセントの縦線＋三角。記録のあるフレームは白の短い縦線、
  S・E の区間は主色の半透明の帯（区間名の札付き）。
- **通知（トースト）**: 白地＋elevation-2＋状態のアイコン＋文言。自動で消えるのは成功の通知だけ。エラーは消さない。
- **ダイアログ**: 白地＋elevation-3、角 12px。見出しは 22px 太字。破壊的な操作の確認では、実行ボタンを主ボタンにせず
  副ボタンにして、操作の内容を文章で示す（例:「12 件を削除します」）。
- **リンク**: 主色・濃の文字＋下線。下線を消さない。マウスを重ねたら下線を太くする。
- **アイコン**: 主色の単色線画（線の太さ 1.5px、24px 格子）でそろえる。

## 7. 使わないもの

- 絵文字、装飾記号（★ など）
- 左端の太い色線による強調
- 大きな数値だけを置いた囲み
- 固定された部分の影、グラデーション、立体表現、ぼかし
- 指定外の有彩色（例外は §2.5 の状態の色、§2.7 の注釈色）
- アクセントを白地・面・主色の上の文字色や細線にすること
- 色だけで状態や区別を伝えること
- 文言: 英語の直訳調（「これにより〜することが可能です」）、原因と対処のないエラー文（「エラーが発生しました」だけ）

## 8. 日本語・英語

- 同じ部品で日本語・英語の両方が収まるよう、ボタンや札の幅を文字の長さに合わせて伸ばす（固定幅にしない）。
  英語は日本語より 1.5〜2 倍長くなることを前提に配置する。
- 用語は用語集で日英を対応させ、画面ごとに訳がぶれないようにする。

## 9. 実装（P2a）

- デジタル庁の `@digital-go-jp/design-tokens`（MIT）を依存に加え、その CSS 変数の上に KemoMichi の役割トークン
  （`color.primary` など）を定義する。部品は必ず役割トークンを参照し、値を直接書かない。
  ライセンス表示は同梱物の一覧（About 画面と配布物）に含める。
- トークンを変えたら `tools/color_check.py` の `PALETTE` も合わせて更新し、計算し直す。
- 確認: 色覚シミュレーション（ブラウザの開発者ツールの色覚エミュレーションでもよい）、白黒表示、
  UI 拡大率 150%、英語表示での見切れ、キーボードだけでの操作。
