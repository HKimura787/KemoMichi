# KemoMichi デザインシステム（第1版）

- 作成日: 2026-10-18
- 対象: KemoMichi のアプリ画面（デスクトップ版・サーバ版の Web UI 共通）
- 状態: 提案段階。P2a の実装開始前に確定する（§10 確認事項）

## 1. 基本方針

- **青を基調**にし、有彩色は役割で **3 つ（主色・面・アクセント）** に絞る。
- 面積の目安は、ベース（白・無彩色）70%、主色と面 25%、アクセント 5%。アクセントは画面の中で
  「いちばん大事な 1 か所」にだけ使う。
- アクセントは主色と**明るさで**区別する（色味の違いだけに頼らない）。
- **色だけで意味を伝えない**。状態や区別には必ず文字・形・アイコンを添える（色覚の違い、
  夜間の赤外線画像のようなモノクロ画面、白黒印刷でも読めるようにする）。
- 区切りは枠線ではなく、面の色の違いと余白で作る。塗りつぶした部品に見える枠線は付けない（§2.4）。
- 影・グラデーション・立体表現は使わない。
- **写真が主役**。画像を見る領域のまわりは色を持たない中間の暗い灰色にし、UI の色が画像の色の
  見え方に影響しないようにする（§2.6）。色味調整（計画書 §6.4）の判断を狂わせないため。
- 色を決める・変えるときは、コントラスト比と色覚シミュレーション（1 型・2 型・3 型）を
  `tools/color_check.py` で計算して確かめる。

## 2. 色

### 2.1 パレット（ライトテーマ）

| 役割 | トークン | 値 | 主な用途 |
|---|---|---|---|
| 主色 | `color.primary` | 青 `#0B4F8F` | 上部バー、選択中の状態、リンク、アイコン、副ボタンの文字と線、見出しの強調 |
| 主色・濃 | `color.primary-strong` | 濃い青 `#073766` | 押している間・選択中にマウスを重ねたとき |
| 面 | `color.surface` | 淡い青 `#E8F0F8` | パネルの見出し行、左右のパネルの背景、表の見出し行、選択していない行の区別 |
| アクセント | `color.accent` | 明るい橙 `#F08A00` | 主ボタン（1 画面に 1 つ）、タイムラインの再生位置、未保存の印 |

無彩色: 本文 `#111111`、補足 `#4A4A4A`、罫線 `#C8C8C8`、白 `#FFFFFF`。

- 主色の青は白に対して 8.30、面に対して 7.22 で、文字にも線にも十分読める。
- 主色・濃は主色と同じ色味の濃淡で、色の数には数えない。
- アクセントの橙は、主色の青と色覚の違いがあっても区別しやすい組合せ（どの色覚でも ΔE 58 以上）。

### 2.2 アクセントの使い方

- 使う場所
  - **主ボタン**: その画面でいちばん大事な操作 1 つ（例:「読み込む」「書き出す」「計測を確定」）。
    塗りはアクセント、文字は本文黒の太字（7.50）。**白い文字は載せない**（2.52 で不可）。
  - **タイムラインの再生位置**（動画・連続画像の現在位置を示す縦線と三角）。
  - **未保存・同期待ちの印**（小さな四角＋「未保存」の文字）。
  - 主色の上ではアクセントを線・塗り・大きな太字（18.66px 以上の太字）に使ってよい（3.30）。
- 使わない場所
  - 白・面の上の文字色、細い線（白に 2.52、面に 2.19 で不可）
  - フォーカス表示、リンクの下線（フォーカスの黄と取り違えないため。§2.5）
  - エラーの表示とその近く
  - グラフの系列、種の色分け（§2.7 の注釈色を使う）
- 面積は全体の 5% 前後に収める。

### 2.3 コントラスト比（`tools/color_check.py` で計算）

文字は 4.5:1 以上（18.66px 以上の太字・24px 以上の文字は 3:1 以上）、線・アイコン・部品の境界は 3:1 以上。

| 前景 | 背景 | 比 | 使い方 |
|---|---|---:|---|
| 白 | 主色 | 8.30 | 可: 上部バーの文字、選択中のチップの文字 |
| 主色 | 白 | 8.30 | 可: リンク、強調文字、アイコン、副ボタン |
| 主色 | 面 | 7.22 | 可: パネル見出しの文字・アイコン |
| 白 | 主色・濃 | 12.02 | 可 |
| 本文黒 | 面 | 16.41 | 可 |
| 補足灰 | 白 / 面 | 8.86 / 7.70 | 可: 注記、ファイル名、時刻 |
| 本文黒 | アクセント | 7.50 | 可: 主ボタンの文字 |
| アクセント | 主色 | 3.30 | 大きな文字・線・塗りのみ可 |
| アクセント | 白 / 面 | 2.52 / 2.19 | **不可**（文字・意味のある線）。主ボタンの塗りには使える |
| 白 | アクセント | 2.52 | **不可**: 主ボタンに白い文字を載せない |
| 面 | 白 | 1.15 | 面の区別だけに使い、境界の意味を持たせない |
| エラー赤 | 白 | 5.66 | 可: エラー文言 |

### 2.4 枠線

- 塗りつぶした部品（ボタン、チップ、選択中の行、バー）の枠線は塗りと同じ色にする（見える枠を付けない）。
- 例外: 塗りが背景とほとんど区別できない（コントラスト比 1.5 未満。白と面は 1.15）うえに、
  部品そのものに意味がある場合（押せるボタン、入力欄、浮かぶパネル）だけ枠線を付ける。
  - 押せる部品（副ボタン、入力欄）: 主色の線 1px。マウスを重ねたら 2px。
  - 浮かぶパネル（メニュー、ダイアログ、コマンドパレット）: 罫線灰 `#C8C8C8` の 1px。影は使わない。
- 余白や配置だけで区切りがわかるもの（パネルの中の段落、カード状のまとまり）には枠線を付けない。

### 2.5 操作状態の色（例外色。装飾には使わない）

| 状態 | 表示 |
|---|---|
| フォーカス | 黄 `#FFD43D` と黒の二重線（外側 黄 2px＋内側 黒 2px）。どの部品でも同じ。キーボード操作が中心のアプリなので、常にはっきり見えることを優先する |
| 選択中 | 主色の塗り＋白文字、または主色の 3px の線（サムネイル）＋左上に選択番号。フォーカス表示とは形で区別できる |
| マウスを重ねた | 面の色の塗り（白地の上）。文字の色は変えない |
| 無効 | 補足灰の文字＋罫線灰の線。「使えない理由」をツールチップで示す |
| エラー | 赤 `#D10000`（白に 5.66）の文字と、エラー用の線画アイコン。必ず文言を添える（例:「整数を入力してください」） |
| 警告 | 本文黒の文字＋主色の警告アイコン＋面の色の帯。赤は使わない（エラーと区別するため） |
| 成功・保存済み | 主色の線画アイコン＋「保存しました」の文字。緑は使わない |

アクセントとフォーカスの黄の差は 2 型の色覚で ΔE 12.3、エラー赤との差は ΔE 19.2。
いずれも形（塗り／二重線／文字色）でも区別できるようにしてあるので、色だけで取り違えることはない。

### 2.6 画像ビューアの色

- 画像の周囲（ビューア・動画プレイヤー・拡大鏡の背景）は**色を持たない暗い灰色 `#2B2B2B`**。
  ライトテーマでも同じ。UI の青が画像の色の見え方に影響しないようにする。
- ビューア上のボタン・時刻表示は白（14.16）。再生位置のアクセントは 5.62 で見える。
- サムネイル一覧の背景も同じ灰色にする。

### 2.7 画像上の注釈色（例外色）

BBox・ポイント・キーポイント・ガイド図形は、さまざまな写真（昼の緑、夜の赤外線のモノクロ、逆光）の
上に重ねるため、UI の 3 色とは別に**注釈専用の色**を持つ。

- 種などの区別には、色覚の違いに配慮して作られた 8 色の配色（Okabe & Ito, 2008）を使う:
  `#E69F00` 橙、`#56B4E9` 空色、`#009E73` 青緑、`#F0E442` 黄、`#0072B2` 青、`#D55E00` 朱、
  `#CC79A7` 赤紫、`#FFFFFF` 白。
- **どんな写真の上でも見えるよう、線と点には黒の縁取り（1px）を付ける**。ラベルは
  黒地に白文字の小さな札にする。
- **色だけで区別しない**: BBox・ポイントには必ず種名（または略号）と番号の札を付ける。
  キーポイントは部位ごとに形（丸・四角・三角）も変える。
- ガイド図形（REST の領域など）は既定で白の線＋黒の縁取り、塗りは半透明（不透明度 15%）。利用者が変更できる。
- AI の候補は破線、人が確定したものは実線で区別する（色は同じ）。
- 割り当ては利用者が変更でき、9 種目以降は形と札で区別する。

### 2.8 ダークテーマ

長時間の作業や暗い部屋での作業向けに用意する。色の役割はライトテーマと同じ。

| 役割 | 値 | 確認値 |
|---|---|---|
| 背景 | `#16191D` | 文字 `#EDEDED` で 15.06 |
| パネル | `#1F242A` | 文字で 13.35 |
| 面（パネル見出し・選択していない行の区別） | `#1B2A3B` | 文字で 12.45 |
| 主色（明るい青） | `#7DB4EC` | 背景に 8.07、パネルに 7.15。選択中の塗りでは文字を本文黒にする（8.64） |
| アクセント | `#F08A00`（ライトと同じ） | パネルに 6.21 |
| エラー | `#FF6B6B` | パネルに 5.63、背景に 6.35。ライトの赤は暗い地では読めないため明るくする |

### 2.9 グラフ

- 系列は主色の青の単色系列（面 → 主色）を使う。2 系列までは色ではなく形で分ける
  （実線と破線、塗りと白抜き）。系列名は線の横に直接書く。
- 3 系列以上を色で分ける必要があるときは注釈色（§2.7）を使い、凡例ではなく直接ラベルを付ける。
- 値ラベルには分母を併記する（例: 12 / 340 枚）。

## 3. 書体と文字

### 3.1 書体

| 用途 | 書体 |
|---|---|
| UI 全般 | `"Noto Sans JP", -apple-system, BlinkMacSystemFont, "Hiragino Sans", "Yu Gothic UI", sans-serif` |
| 時刻・フレーム番号・数値の列 | 上と同じ書体で**等幅数字**（`font-variant-numeric: tabular-nums`）。タイムコードは `"Noto Sans Mono", ui-monospace, "SFMono-Regular", Consolas, monospace` |

太さは標準 400 と強調 700 の 2 段階。日本語と英語で同じ書体・同じ文字サイズを使う。

### 3.2 文字サイズ（アプリ画面）

アプリは情報量が多いので、Web ページより一段小さい。すべての文字は利用者が UI 全体の拡大率
（90〜150%）で大きくできる。

| 要素 | サイズ / 太さ | 行間 |
|---|---|---|
| ダイアログ・ウィザードの見出し | 20px / 700 | 1.4 |
| パネルの見出し | 16px / 700 | 1.4 |
| 本文・入力欄・ボタン | 14px / 400（ボタンは 700） | 1.6 |
| 表・一覧の行、補足 | 14px / 400 | 1.5 |
| ツールチップ、ショートカットの表示、画像上の札 | 12px / 700 | 1.4 |

12px 未満は使わない。字間は 0（日本語は詰めない）。

## 4. 間隔・寸法

- 4px 単位で設計する（4 / 8 / 12 / 16 / 24 / 32）。
- 押せる部品の大きさは最小 32px（マウス操作）、タッチ操作のある画面は 44px。
- 角の丸み: ボタン・入力欄・チップ・タイムラインの区間の帯は **4px**。パネル、バー、表、画像、
  サムネイルは**直角**。ダイアログは直角。
- 線の太さ: 区切り 1px、選択中 3px、フォーカス二重線 合計 4px。

## 5. 画面の構成

- **上部バー**: 主色の塗りに白文字。プロジェクト名、接続先（「この PC」／サーバ名）、保存状態、
  言語切替、設定。高さ 44px。
- **3 ペイン**: 左（フォルダとフィルタ）・中央（ビューア／グリッド）・右（データ入力）。
  左右のパネルは白地、パネルの見出し行は面の色。中央はビューアの灰色（§2.6）。
- **下部**: 動画・連続画像のタイムライン（中央ペインの下）。背景はビューアの灰色、再生位置はアクセント。
- ペインの境界は面と白の違い、または 1px の罫線灰で示す。

## 6. 部品

- **主ボタン**: アクセントの塗り＋本文黒の太字。1 画面に 1 つまで。枠は付けない。
- **副ボタン**: 白地＋主色の文字＋主色の 1px の線。
- **控えめなボタン**（ツールバーのアイコンボタン）: 塗りなし、主色のアイコン。マウスを重ねると面の色。
  アイコンだけのボタンには必ずツールチップ（機能名＋ショートカット）を付ける。
- **入力欄**: 白地＋主色 1px の線。エラー時は赤の線 2px＋下にエラー文言。
- **チップ**（フィルタ条件、選択中の種）: 選択中は主色の塗り＋白文字、未選択は面の塗り＋主色の文字。
  チップには必ず文字を入れる。削除ボタン（×）付き。
- **種選択パレット**: 種ごとのボタン（最小 44×44px）に、種名・割り当てキー・個数を表示。
  ON は主色の塗り＋白文字＋左上に小さな四角の印、OFF は白地＋主色の線。ON/OFF は色に加えて印の有無でも区別する。
- **表**: 見出し行は面の色、本文行は白。縦の罫線は引かず、横の区切りは罫線灰の 1px。
  選択中の行は主色の塗り＋白文字。
- **サムネイル**: 直角。選択中は主色の 3px の線＋左上に選択番号の札。削除フラグ付きは右上に
  「削除」の札（色だけで示さない）。
- **タイムライン**: 再生位置はアクセントの縦線＋三角。記録のあるフレームは主色の短い縦線、
  S・E の区間は主色の半透明の帯（区間名の札付き）。
- **トースト通知**: 白地＋罫線灰の線＋主色のアイコン＋文言。自動で消えるのは成功の通知だけ。エラーは消さない。
- **ダイアログ**: 白地＋罫線灰 1px。見出しは 20px 太字。破壊的な操作の確認では、実行ボタンを主ボタンにせず
  副ボタンにして、操作の内容を文章で示す（例:「12 件を削除します」）。
- **リンク**: 主色の文字＋下線。下線を消さない。
- **アイコン**: 主色の単色線画（線の太さ 1.5px、24px 格子）でそろえる。

## 7. 使わないもの

- 絵文字、装飾記号（★ など）
- 左端の太い色線による強調
- 大きな数値だけを置いた囲み
- 影、グラデーション、立体表現、ぼかし
- 指定外の有彩色（例外は §2.5 の操作状態の色、§2.7 の注釈色）
- アクセントを白地・面の上の文字色にすること
- 色だけで状態や区別を伝えること
- 文言: 英語の直訳調（「これにより〜することが可能です」）、曖昧な言い方（「エラーが発生しました」だけで原因と対処を書かない）。
  エラー文言は「何が起きたか」と「どうすればよいか」を書く。

## 8. 日本語・英語

- 同じ部品で日本語・英語の両方が収まるよう、ボタンや札の幅を文字の長さに合わせて伸ばす（固定幅にしない）。
  英語は日本語より 1.5〜2 倍長くなることを前提に配置する。
- 用語は用語集（P0 で作成）で日英を対応させ、画面ごとに訳がぶれないようにする。

## 9. 実装（P2a）

- 色・文字・間隔・角の丸みは**デザイントークン**として 1 か所に定義し（CSS 変数）、部品は必ずトークンを参照する。
  値を直接書かない。
- ライト／ダークはトークンの切替だけで済むようにする。
- トークンを変えたら `tools/color_check.py` の `PALETTE` も合わせて更新し、計算し直す。
- 確認: 色覚シミュレーション（ブラウザの開発者ツールの色覚エミュレーションでもよい）、
  白黒表示、UI 拡大率 150%、英語表示での見切れ、キーボードだけでの操作。

## 10. 確認事項

| 項目 | 内容 |
|---|---|
| 主色の青 | `#0B4F8F` を提案。もっと明るい青・紺寄りがよければ、同じ条件（白に 4.5 以上、アクセントと 3:1 以上）で候補を出し直す |
| アクセント | 明るい橙 `#F08A00` を提案。青と対になり色覚の違いにも強い。黄寄りにするとフォーカス表示の黄と近づくため勧めない |
| 既定のテーマ | ライトを既定にし、ダークを選べるようにする案。画像の周りは両テーマとも暗い灰色 |
| 注釈色 | 8 色の配色を既定にする案。種ごとの色を固定したい（例: ある種は常に同じ色）かどうか |
