# KemoMichi MVP（v0.1.0）の使い方

この版は「触りながら詳細を詰める」ための最初の動く版です。計画書の P2a（基本のタグ付け）と、
P2b のうち REST 計測の中核（補助線、有効範囲での滞在イベント）を入れています。

## 1. 起動する

必要なもの: [uv](https://docs.astral.sh/uv/)（推奨）または Python 3.11 以上。動画を扱う場合は ffmpeg
（`ffmpeg` と `ffprobe` にパスが通っていること）。Windows / macOS / Linux で同じ手順です。

### uv を使う（推奨）

uv は Python 本体も自動で用意するので、Python を別に入れる必要はありません。

```bash
git clone https://github.com/HKimura787/KemoMichi.git
cd KemoMichi
uv sync                                   # 初回だけ。.venv を作って依存関係を入れる

# まずはデモで試す（ダミーの画像・動画と見本テンプレートを作る。実データは使わない）
uv run kemo demo ~/kemomichi-demo
uv run kemo serve ~/kemomichi-demo/TimelapseTemplate.ddb
```

どのフォルダからでも `kemo` で起動したい場合は、コマンドとして入れます。

```bash
uv tool install .                         # KemoMichi のフォルダで実行
kemo serve                                # 以後どこからでも
uv tool upgrade kemomichi                 # 更新したとき（git pull の後）
```

### pip を使う

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate   macOS/Linux: source .venv/bin/activate
pip install -e .
kemo demo ~/kemomichi-demo
kemo serve ~/kemomichi-demo/TimelapseTemplate.ddb
```

ブラウザが自動で開きます（開かなければ <http://127.0.0.1:8765/>）。
自分のデータで試すときは `kemo serve`（uv なら `uv run kemo serve`）だけで起動し、画面から `.ddb` を選びます。
「既存のddbを開く・再開」で「ファイル・フォルダのパス」にフルパスを貼り付けると、
フォルダの場合は中のddbを選べ、ddbファイルの場合はEnterで直接開けます。
パスを入力した場合も「読み取り専用で開く」を利用できます。サーバ利用時は、サーバ上の許可されたフォルダ内のパスを指定します。

「tdbから新規作成」では、画像・動画フォルダを選んでからテンプレートを指定します。
テンプレート選択画面でもファイル・フォルダのパスを入力できます。
続いて入力項目・選択肢・初期値などを編集し、確認画面で確定してからddbを作成します。
確定版tdbとddbは、指定したプロジェクト名と同じ基本名で保存します。元のtdbと既存ファイルは上書きしません。
同名ファイルがあるときは別名を提案します。詳しくは [tdb編集の手順](template-editor.md) を参照してください。
CLIの `kemo new` とデモ作成は、従来どおり元のtdbと同じ名前でddbを作ります。

判読位置（ファイル・動画フレーム・絞り込み・表示モード）は `.ddb.kemomichi` に保存し、
次に同じddbを開くと再開します。読み取り専用のときは新しい位置は保存しません。
出力CSVはddbと同じ基本名です（例: `調査.ddb` → `調査.csv`）。

メニューの「別のプロジェクトを開く」から選択画面へ移動した場合は、「メイン画面に戻る」または Esc で
作業中の画面へ戻れます。別のプロジェクトを開くまでは、選択中の画像や絞り込み条件を保持します。

**初めて自分のデータで使うときは、必ずプロジェクトのフォルダごとコピーを取ってから**試してください。
KemoMichi も書き込み前に `Backups/` にバックアップを作りますが、MVP のためです。

### サーバとして動かす（研究室の共有 PC など）

```bash
kemo serve --host 0.0.0.0 --password 共有パスワード --root /data/camera
```

- ネットワークに公開するときはパスワードと `--root`（開いてよいフォルダ）が必須です。どちらかがないと起動しません。
- 他の PC からはブラウザで `http://サーバのアドレス:8765/` を開きます。
- MVP では、同時に開けるプロジェクトはサーバ全体で 1 つです（複数人が同じプロジェクトを編集するのは可。
  同じ画像を同時に編集したときの競合表示は P5 で入れます）。

## 2. 画面

- **左**: フォルダ（カメラ）一覧と絞り込み（種、種が未入力、削除フラグ、検索、AI 検出）。
- **中央**: 1 枚表示（ズームはホイール、移動はドラッグ）と一覧（クリック、Shift / Ctrl で複数選択）。
- **右**: データ入力。上から 種選択パレット → 種ごとの個数 → 滞在イベント → そのほかの項目 →
  色味・明るさ → 補助線。
- 上部バー: 保存状態（入力はその場で保存されます）、元に戻す / やり直す、日本語 / English、メニュー。

## 3. 主な操作

| キー | 動作 |
|---|---|
| ← / → | 前 / 次のファイル |
| 1 … 9, 0 | 種の ON/OFF（設定で割り当て）。一覧で複数選択中なら全部に適用 |
| , / . | 動画を 1 フレーム戻す / 進める（Shift で 10） |
| Space | 動画の再生 / 一時停止 |
| S / E | 有効範囲への侵入 / 退出。動画はフレーム、静止画は画像単位 |
| Shift+S / Shift+E | 動画開始前から侵入済み / 動画終了まで退出せず |
| G / B | 補助線 / AI の枠の表示切替 |
| A（押している間） | 色味調整の前を表示 |
| V | 1 枚表示と一覧の切替 |
| F | 全体表示に戻す |
| D | 削除フラグの切替 |
| Ctrl+Z / Ctrl+Shift+Z | 元に戻す / やり直す |
| ? | ショートカット一覧 |

## 4. 最初にする設定（メニュー → 設定）

1. **種選択パレット**: 種として使う Flag 項目、個数の項目、数字キーを選びます。
   個数の項目がない種は「種ごとの個数を追加」で、テンプレート（.tdb）とデータファイル（.ddb）の両方に
   Counter 項目を追加できます（追加前にバックアップを取ります。Timelapse2 で開いても同期の確認は出ません）。
2. **滞在イベントの書き込み先**: 獣種・個体 ID・開始前から侵入済み・侵入（秒）・退出したファイル名・退出（秒）・
   終了まで退出せず・滞在時間を入れる項目を選びます。選んだ項目は画面から直接は変更できなくなり、
   イベントの記録からだけ値が入ります。

## 5. この版に入っているもの

- Timelapse2 の `.ddb` を開く・編集・保存（Timelapse2 で開ける形を維持。バージョン番号は書き換えない）
- テンプレート（.tdb）からの新規作成、デモプロジェクトの作成
- 全コントロール型の入力と検証、前のファイルの値をコピー、一覧での一括入力
- 種選択パレット（複数種、種ごとの個数、Flag と個数の連動）、種ごとの個数の項目の一括追加
- 元に戻す / やり直す（このセッションの編集）
- 色味・明るさ調整（明るさ、コントラスト、彩度、ガンマ、グレースケール。カメラ単位の既定値）
- 補助線（直線・三角形・四角形・多角形・円）をカメラ（フォルダ）単位で定義、画像と動画に表示
- 動画のフレーム単位のコマ送り（各フレームの正確な時刻を使用）
- **有効範囲での滞在イベント**: 侵入（S）から退出（E）まで。動画をまたぐイベント、開始前から侵入済み
  （Shift+S）、終了まで退出せず（Shift+E）、1 動画に複数イベント（行を自動で複製）、イベント単位の CSV 出力
- AI 認識結果（MegaDetector / AddaxAI の JSON）の取り込みと枠の表示（Timelapse2 と同じ規則で保存）
- CSV 書き出し（Timelapse2 と同じ書式）
- 日本語・英語の切替、サーバ動作（パスワード必須、フォルダ制限）

## 5.1 滞在イベントの記録手順

1. 動画をコマ送りし、動物が有効範囲に入ったフレームで **S**（種を数字キーで選ぶ）。
   動画の最初からすでに中にいたら **Shift+S**。
2. 同じ動画の中で出たら、そのフレームで **E**。
3. 出ないまま動画が終わったら、そのまま **→** で次の動画へ。右パネルに「継続中」として残ります。
   出た動画・フレームで **E**。最後まで出なかったら **Shift+E**。
4. 一度出て戻ってきたら、別のイベントとして 1 からもう一度。
   同じ動画に複数の個体がいるときは、個体ごとに S を押せば時間が重なっても記録できます。
   個体 ID は自動で通し番号が付き、E のときにどの個体の退出かを選べます。
5. 結果は侵入した動画の行に書き込まれます。1 つの動画に 2 件以上あると行が自動で複製され、
   ツールバーの「記録 n / 合計」で切り替えて確認できます。メニュー →「滞在イベントを CSV に書き出す」で
   1 行 1 イベントの一覧も出せます。

## 6. まだ入っていないもの（次の段階）

- フレーム単位の記録（種・個数・メモ）、手動のポイント・BBox、トラッキング・姿勢（P2b 残り・P4）
- エピソード、QuickPaste、日時補正、削除の実行、フォルダ階層データの入力、テンプレートエディタ（P4）
- 自動レベル補正・局所コントラスト強調（色味調整の追加分）
- 補助アプリの一般公開に向けた署名・公証・配布条件の確認（試用ビルドは [desktop.md](desktop.md)）
- 複数人での同時編集の競合表示（P5）

## 7. 分かっている制約

- Timelapse2 実機で作った見本ファイル（`docs/spec/fixtures-guide.md`）による検証はまだです。
  形式はソースの調査と KemoMichi 自身のテストで確認しています。
- MultiChoice の値は選択肢の並び順で保存しています（Timelapse2 の順序は未確認）。
- 動画の撮影日時はファイルの日時から取っています（Timelapse2 と同じ）。
- H.264 を再生できないブラウザ（一部の Linux 版 Chromium など）では、自動で WebM に変換して再生します。
  初回は変換に少し時間がかかります。

## 8. 開発

```bash
uv sync                    # 開発用の依存関係（pytest など）も入る。pip なら pip install -e ".[dev]"
uv run pytest              # コアとサーバのテスト
cd web && npm install
npm run dev                # 開発用（別ターミナルで kemo serve --no-browser を起動）
npm run build              # src/kemoserver/static に出力（リポジトリに含めています）
```
